**Что делает сервис:**
* **Принимает данные:** Название, производитель, характеристики (в виде словаря) и текстовое описание.
* **Генерирует контент:** На основе входных данных формирует SEO-заголовок (до 70 символов), подробное SEO-описание (800–1200 символов), коммерческий блок для менеджера (кому подходит и какую задачу решает) и около 5 поисковых запросов.

**Что реализовано в MVP:**
* **Строгая типизация:** Благодаря Pydantic (FastAPI) входной JSON валидируется по схеме. Если передать неверный тип данных (например, строку вместо словаря в `specs`), API вернет `422 Unprocessable Entity`, не передавая данные в LLM.
* **Проверка обязательных полей:** Если отсутствуют ключевые данные (`name`, `manufacturer`), сервис не вызывает LLM, а мгновенно возвращает статус `needs_clarification` со списком недостающих полей (согласно ТЗ).
* **Защита от XSS:** На фронтенде вывод данных осуществляется через `textContent` (а не `innerHTML`), что исключает выполнение вредоносных скриптов, если они попадут в JSON.

### Установка зависимостей
Создайте виртуальное окружение и установите пакеты:
```bash
python -m venv .venv
# Windows: .\.venv\Scripts\Activate.ps1
# Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

## Как запустить и проверить

**Создать .env в корне проекта**

Есть два варианта запуска: локально и с любым вашим API-ключом.
1. Локально (например, ollama) поместить в .env (в корне проекта):

```
LLM_API_KEY=ollama
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen2.5
USE_MOCK=0
```

2. API LLM (поместить в .env). Пример для groq:
```
LLM_API_KEY=gsk_ваш_ключ
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=llama3-8b-8192
USE_MOCK=0
```

3. Тест без LLM (Mock-режим)
Поставьте ```USE_MOCK=1``` в .env
Полезно для проверки работы валидации, API и фронтенда без запросов к LLM

Запустите сервер:
```commandline
uvicorn app.main:app --reload
```
Перейдите на http://127.0.0.1:8000, вставьте данные товара и нажмите "Сгенерировать"


## Дальнейшие потенциальные улучшения
* **Факт-чекинг** (Сверка цифр в тексте с `specs`) -> 100% гарантия отсутствия искажений технических данных.
* **Двухэтапная генерация** (Сначала извлечение фактов, затем текст) -> Снижение когнитивной нагрузки на LLM и повышение точности.
* **Асинхронность** -> Фоновая генерация без зависания интерфейса (актуально для локальных моделей).
* **Fallback-механизм** (Автопереключение между облачным API и локальной моделью)
* **Защита от Prompt Injection:** Добавление санитайзера, который будет вырезать из входного текста фразы, пытающиеся переопределить системный промпт (например, "игнорируй инструкции").
* **Семантическая валидация:** Проверка того, что переданные `specs` соответствуют типу товара
